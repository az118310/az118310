# 求职作品集 · AI 客服 Agent

> 项目定位：**把淘宝售前客服的 SOP 与话术，沉淀成一个可上线的 AI 客服 Agent**
>
> 目标读者：面试官 / 技术负责人
> 一句话价值：用 RAG + Tool Calling + MCP，把售前重复咨询的响应时间从 X 分钟降到 Y 秒，同时保证合规不乱承诺

---

## 为什么这个项目值得做

转行做 AI 应用的人，90% 做的是「聊天机器人 Demo」——换个问法就崩，没有业务闭环，面试官一问就露馅。

这个项目不一样：

| 维度 | 普通 Demo | 这个项目 |
|---|---|---|
| 数据 | 网上爬的语料 | 真实电商客服场景 + 真实 SOP 规则 |
| 评估 | 没评估，凭感觉 | 100 条评测集 + 量化指标 |
| 安全 | 没考虑 | 合规红线拦截 + 越权拒绝 + 防幻觉 |
| 部署 | 只能本地跑 | 在线可访问 URL + Docker 一键部署 |
| 成本 | 不算 | 有 Token 成本统计和优化 |
| 业务闭环 | 无 | 意图分流 → 知识检索 → 工具调用 → 话术生成 → 人工兜底 |

**面试时能讲的东西**：架构选型理由、检索策略为什么这么设计、bad case 怎么定位优化、成本怎么降、准确率怎么提。这些才是「生产级项目落地经验」的真正含义。

## 面试时怎么讲这个项目（30 秒版）

> "我是从淘宝售前客服转 AI 应用的。我发现售前有大量重复咨询——发货时效、尺码推荐、退换政策，这些占了咨询量的七成，而且话术是标准化的。
>
> 我把店铺的 SOP 和商品资料做成了知识库，用 RAG 加上意图分流，再用手写的 Tool Calling 循环去查实时订单和物流。整个 Agent 有合规拦截层，销售话术里的绝对化用语会被挡掉，功效类表述会自动加限定词。
>
> 上线前我准备了 100 条评测集跑量化评估，最初意图分类准确率只有 71%，我定位到 bad case 主要是复合意图和口语化表达，调整了分类 prompt 和追问策略后提到 87%。
>
> 最终项目部署在公网，Demo 在这里（链接），评估报告和架构文档都在 GitHub。"

**这段话里每个数字都有出处**，面试官追问任何一个你都能展开 5 分钟。这才是「生产级项目落地经验」。

## 简历上的写法

```
AI 客服 Agent 系统 (个人项目 / 电商售前咨询场景)          2026.11 - 2026.12
├── 基于 LangGraph 构建多步 Agent 编排，实现「意图识别 → 知识检索 →
│   工具调用 → 话术生成」全链路，端到端响应 < 2s
├── 构建 RAG 知识库（商品资料 + FAQ + 客服 SOP），混合检索
│   (向量 + BM25) + Reranker 重排，100 条评测集问答正确率 87%
├── 设计合规拦截层，拦截绝对化用语与越权承诺，拦截率 100%（62/62 用例）
├── 手写 Tool Calling 执行循环 + MCP Server 对接订单/物流工具，
│   工具调用成功率 96%
├── Docker + Nginx 部署上线，提供公网访问地址
技术栈: Python / LangChain / LangGraph / LlamaIndex / MCP / RAG /
        FastAPI / Chroma / Docker / Nginx / GitHub Actions
```

> ⚠️ 上面的数字是**目标值**，等你在对应阶段实测出来后再填。**不要填你没测过的数字**——面试官追问「87% 是怎么算的」答不上来，比数字低得多更致命。
