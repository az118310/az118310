# 每日笔记模板 —— 复制到 notes/daily/ 使用

> 规则：**每天不超过 5 行**。写太长就没人写了。
> 目的不是记笔记，是**给明天的自己留一个起点**——避免第二天早上对着空白编辑器发呆。

---

```markdown
# YYYY-MM-DD（周X）

**今天做完的**：（一句话，具体到哪个文件/哪个功能）
**卡住的**：（一个问题，明天第一件事解决它）
**明天第一件事**：（具体到可以直接动手，不要写"继续学习"）
**时间**：晚间 Xh + 午休 Xmin + 通勤 Xh = 合计 Xh
```

---

## 示例

### 2026-10-22（周四）
**今天做完的**：写完 Python 异常处理练习，`scripts/data_report.py` 能读 CSV 出报表
**卡住的**：装饰器还是不太懂，看不懂 `@property` 的用法
**明天第一件事**：用 `property` 把 data_report.py 的字段访问改一遍（30 分钟）
**时间**：晚间 2.5h + 午休 0.5h + 通勤 2h = 5h

### 2026-10-26（周一）
**今天做完的**：跑通 `basic_call.py`，第一次拿到模型回复，token 用量 342
**卡住的**：一开始设了 `temperature=0.3` 但回复还是发散，改成 0.1 + 加 system 约束好了
**明天第一件事**：写 `prompt_lab.py`，同一 prompt 写 3 个版本对比
**时间**：晚间 2.5h + 午休 1h + 通勤 2h = 5.5h
```

## 连续断更怎么办

**断 1 天**：正常，不补，直接接上。
**断 2 天**：把目标降到"读文档 + 跑一遍现有代码"，先找回手感。
**断 3 天以上**：**立刻重启**，但把目标降到最低——今晚只做"打开项目、读一遍上次代码、跑通它"。做完就算赢。

**不要因为断更就放弃整个计划。** 断更一周可以重来，断更两个月就彻底凉了。
